## what this is

How to build, run, and release URSA.

## technical map

**build (from project root)**
```bash
export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"
./gradlew.bat assembleDebug --no-daemon     # -> app/build/outputs/apk/debug/app-debug.apk
./gradlew.bat testDebugUnitTest --no-daemon # unit tests
./gradlew.bat :app:lintDebug --no-daemon    # must pass before commit
```

**run**
- Install the debug APK on a device/emulator, or Run from Android Studio.
- Point it at the dev Kuma at `http://10.0.2.2:3001` (emulator) or the LAN IP.

**release**

1. Prepare a release PR. Update `CHANGELOG.md`, both modules' literal
   `versionName` and `versionCode`, `fdroid/dev.astoris.ursa.yml`, and
   `fastlane/metadata/android/en-US/changelogs/<versionCode>.txt`. The version code
   is `major*10000 + minor*100 + patch`.
2. Run the local build, tests, lint, F-Droid metadata validator, screenshot
   baseline validator, and immutable Action-pin validator. Merge only after the
   hosted checks pass.
3. Create the `vX.Y.Z` tag and GitHub release from the release merge commit.
4. Run the **Release artifacts** workflow with that existing tag. It builds and
   uploads signed phone and watch APKs, a CycloneDX SBOM, checksums, and provenance.
5. Download the assets and verify the checksums, APK signatures/version metadata,
   and attestations. F-Droid discovers the version tag automatically.

**release screenshots**
- Regenerate README and F-Droid screenshots only after feature and UI work is
  final. Include both the primary monitoring views and a monitor-list capture
  with the three-dot menu expanded so the otherwise hidden feature list is clear.
- Keep secrets, server addresses, credentials, and personal data out of every
  capture; verify both the rendered images and their accessibility descriptions.

## gotchas

- First build downloads Gradle 9.4.1 (~130 MB) + AGP/deps - slow once, cached
  after.
- Use `--no-daemon` in CI/headless to avoid lingering daemons on Windows.
- lint caches results; if a `local.properties`-style fix seems ignored, rerun
  with `--rerun-tasks`.
