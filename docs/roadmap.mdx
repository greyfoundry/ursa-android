## what this is

URSA's direction after completing its original viewer, actions, push, native-depth,
competitor-parity, and UI-revamp programmes. This is a priorities document, not a
promise of dates. Completed implementation detail lives in
`docs/planning/mobile-competitor-parity.mdx`.

## completed foundation

- Native phone monitoring with live state, history, certificate data, public status
  pages, offline cache, multi-server switching, and responsive phone/tablet layouts.
- UnifiedPush without Firebase or a hosted relay, including managed Kuma setup,
  transition policy, quiet hours, delays, repeats, severity, and local actions.
- Android integrations: app lock, widgets, Quick Settings tile, shortcuts, scoped
  deep links, certificate/update notifications, and an opt-in glance display.
- Native incident, certificate, domain, event, aggregate, and pinned-live views.
- Safe common monitor CRUD, groups, tags, notification assignment, bulk actions,
  six maintenance strategies, and local service discovery.
- Encrypted backups, encrypted access headers, saved advanced filters, diagnostics,
  and a manual official-release check.
- A separate Wear OS dashboard, detail view, tile, complications, and optional
  same-signed phone pairing for private servers.

## next priorities

1. Finish advanced monitor-type-specific creation only where a native form is safer
   and clearer than opening Kuma. Existing unknown fields must remain round-trip safe.
2. Improve localization coverage and welcome community translations.
3. Continue accessibility, performance, large-fleet, and older-device testing.
4. Add issue-driven integrations only when they fit the existing connection and
   network abstractions without creating a second configuration system.

## deliberate boundaries

- No hosted relay, account service, analytics, advertising, or paid tier.
- No replacement for Kuma's user, database, API-key, Docker-host, remote-browser,
  or server administration UI.
- No background polling by default. UnifiedPush and explicitly enabled Android
  jobs provide background behavior.
- No raw JSON editor for monitor configuration.

## project infrastructure

- CI builds, tests, lints, validates metadata/screenshots, and scans dependencies.
- Dependabot covers Gradle and GitHub Actions; CodeQL and action-policy workflows
  run in GitHub.
- Releases are prepared and published manually from a reviewed release commit.
- F-Droid discovers normal `vX.Y.Z` tags and builds the phone app independently.
