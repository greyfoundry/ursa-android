## sub-milestone 1: offline last-known status (design)

**Goal.** On launch, the monitor list appears immediately from the last saved
snapshot (with a "last updated <time>" line) instead of an empty screen, then live
data takes over as the socket reconnects.

**Shape.**
- A pure `MonitorSnapshot` model (serializable) plus pure encode/decode and a
  "should show cache" decision - unit-testable on the JVM.
- An Android-side store that persists the snapshot per active server, encrypted at
  rest with the existing `Crypto` (monitor names and URLs are infrastructure detail,
  so they get the same protection as credentials).
- The repository writes a snapshot whenever the live monitor list updates, and seeds
  its `monitors` StateFlow from the snapshot on init so the UI has data at once.
- The UI shows a subtle "Last updated <relative time>" indicator when displaying
  cached (not-yet-live) data.

**Reconciliation.** Live data always wins: when the socket delivers a non-empty
monitor list, it replaces the cache in the flow and is written back as the new
snapshot. The cache is per active-server; switching servers loads that server's
snapshot.

**Out of scope.** Caching heartbeat history or certificates (list + status only for
now). No background refresh - the cache is a fast first paint, not a sync engine.
