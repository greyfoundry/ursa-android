### 2026-07-04 - first on-device run (Pixel 8): 3 bugs found + fixed, theme verified

**environment**: A Pixel_8 AVD (system image android-37) is now available. Verified via
`adb` install/launch/screencap against a live dev Kuma (seeded 3 monitors). Emulator
and android-37 are now provisioned (previously blocked).

**bugs found on device (none caught by unit tests) and fixed**:
1. **Startup crash** - `MonitorRepository` init block collected `certs` before that
   property was initialized (declared after `init`), NPE on launch. Moved `state` +
   `certs` above `init`. This crashed the app on every launch since M4 #4.
2. **Dark mode broken** - `Theme.URSA` was a light-only framework theme; added a
   `values-night/` theme + day/night `window_bg` color so the app follows the system
   dark setting.
3. **Invisible dark-mode text** - login/status-page screens are not wrapped in a
   Scaffold/Surface, so default content color was black on the dark background.
   `UrsaTheme` now wraps content in a `Surface(color = background)`.
Also gated `FLAG_SECURE` to release builds only (skipped when debuggable) so
screenshots work in development.

**verified working end-to-end**: login over Socket.IO, live monitor list with Kuma
status pills (Up green / Down red / Pending orange) in rounded cards, monitor detail
with the Kuma heartbeat bar and TLS certificate parsing, in both light and dark mode.
Colors match Uptime Kuma exactly.

### 2026-07-04 - M3 phase 1: UnifiedPush receive path (PushService + notifications)

**changed**: New `core/push` module. Added connector 3.3.3 dependency (excluding its
JVM `tink` to avoid a duplicate-class clash with our `tink-android`). Manifest:
`POST_NOTIFICATIONS` permission + a NON-exported `UrsaPushService` handling
`PUSH_EVENT`. `UrsaPushService` (extends `PushService`) captures the endpoint on
`onNewEndpoint`, and on `onMessage` parses Kuma's webhook JSON and posts a system
notification (permission-guarded, channel `ursa_monitors`). `PushParse` = pure,
tolerant parser of `{heartbeat, monitor, msg}` → `PushNotice`. `PushStore` =
process-wide endpoint/distributor holder (SharedPreferences + StateFlow).

**decisions made**:
- **`PushService`, not the deprecated `MessagingReceiver`** - verified against
  connector 3.3.3 source. Bonus: it's `exported="false"`, so the M3 security gate
  (no exported push surface) is satisfied by construction.
- No VAPID/web-push encryption: Kuma POSTs plain JSON, so messages arrive
  unencrypted (`decrypted=false`); push body treated as untrusted, render-only.
- Endpoint URL kept in plain SharedPreferences (delivery address, not a credential).

**next**: phase 2 = registration UI (pick distributor, show endpoint + copy, request
POST_NOTIFICATIONS); phase 3 = PushParse unit tests + module/security doc updates.
