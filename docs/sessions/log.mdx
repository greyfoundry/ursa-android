### 2026-08-31 - per-monitor severity and stable Android channels

**changed**: Completed parity item CP-023. Each managed monitor now has a separate
critical, standard, or silent delivery severity in addition to its transition
mode. The setting is device-local and server-scoped, defaults to the previous

### 2026-08-27 - server-scoped per-monitor push modes

**changed**: Completed parity item CP-022. Each monitor on a current managed Kuma
Webhook can now use one of four device-side alert modes: muted, down-only,
down-and-recovery, or all transitions. The compact selector sits separately from
Kuma's provider-assignment checkboxes, applies immediately, and persists across
process restarts.

**identity and compatibility boundary**: Managed providers now use Kuma 2.5.3's
custom Liquid Webhook body to include a random 32-hex server scope alongside the
standard heartbeat, monitor, and message fields. Policies are keyed by that scope
and monitor ID, so identical numeric IDs on different servers cannot collide. The
scope contains no connection metadata. Legacy and manual Webhooks without a valid
scope retain all-transition behavior so upgrading cannot silently suppress alerts;
removing the managed provider clears its local policy entries.

**verification**: The 101-test suite covers every status/mode combination, managed
template fields, scope validation, config parsing, and push parsing. Android lint,
debug assembly, and release assembly passed. Android 17 QA against official Kuma 2.5.3

### 2026-08-25 - password-encrypted configuration backup

**changed**: Completed parity item CP-005. The saved-server manager can export and
import a versioned `.ursa.json` document through Android's system document picker.
The encrypted payload carries connections, access headers, favorites, dynamic
