# Publishing URSA on F-Droid

URSA is listed at https://f-droid.org/packages/dev.astoris.ursa/. The phone app's
`fdroid` flavor is fully FOSS and contains no Firebase, Google Play Services,
analytics, or hosted relay. The release workflow publishes this exact flavor as
`ursa-fdroid-vX.Y.Z.apk` for reproducible-build comparison. The separate GitHub Wear
APK is distributed outside F-Droid.

## Repository surfaces

- `fastlane/metadata/android/en-US/` is the source for listing text, changelogs,
  icon, feature graphic, and phone screenshots.
- `fdroid/dev.astoris.ursa.yml` mirrors the active fdroiddata recipe for review.
- The canonical source repository is `https://github.com/greyfoundry/ursa-android`.

## Per-release upkeep

1. Update the literal phone and Wear `versionName`/`versionCode` values and add the
   matching Fastlane changelog.
2. Update `fdroid/dev.astoris.ursa.yml` to the same commit and version. Its Gradle
   flavor must be `fdroid`, and `Binaries` must point to the matching F-Droid APK.
3. Refresh screenshots after UI work. Include the primary monitor view, monitor
   detail, light mode, connection flow, and the open three-dot feature menu.
4. Follow the manual release checklist in `docs/infrastructure/deployment.mdx` and
   publish a normal `vX.Y.Z` tag.

`AutoUpdateMode: Version` and `UpdateCheckMode: Tags ^v[0-9]` let F-Droid discover
future version tags automatically. F-Droid then updates its own build recipe and
builds/signs the APK independently; no GitLab action is normally required for each
release unless its bot or maintainers report a recipe failure.

## Signing boundary

F-Droid signs its build with the repository's established F-Droid signing identity.
The GitHub release keystore and workflow secrets are used only for GitHub Release
artifacts. Never copy release keys or credentials into fdroiddata, Fastlane metadata,
screenshots, or public documentation.
