## what this is

The screens and the single ViewModel behind them. One `UrsaViewModel` holds all
app state; a top-level `when` in `UrsaApp` picks the screen from that state (no
navigation library for M1 - the screen set is small and state-driven).

## technical map

**file paths**
- `.../ui/UrsaViewModel.kt` - AndroidViewModel; owns `MonitorRepository` +
  `StatusPageClient`; login, saved-server, and saved public-page flows, selection,
  status-page state, pause/resume, and per-server favourites.
- `.../ui/UrsaApp.kt` - root; routes server manager / status-page / login /
  detail / list.
- `.../ui/connections/LoginScreen.kt` - optional server name, URL, password or
  imported session-token authentication, conditional 2FA, connection test, and
  explicit self-signed-certificate choice. Its collapsed access-header editor
  supports masked Cloudflare Access credentials and up to eight custom headers.
- `.../ui/connections/ConnectionManagerScreen.kt` - add, switch, rename, and
  confirmed removal of encrypted saved-server sessions, plus password-encrypted
  document export/import.
- `.../ui/monitors/MonitorListScreen.kt` - live list, tappable rows, local groups,
  and attention/favourite/name sorting.
- `.../ui/monitors/MonitorDetailScreen.kt` - heartbeat bar strip, incident timeline,
  favourite toggle, cert, pause/resume.
- `.../ui/statuspage/StatusPageScreen.kt` - unlimited encrypted local public-page
  manager with add/edit/remove, favourite, ordering, refresh, and native viewing.
- `.../ui/StatusUi.kt` - status -> Kuma color / label string-resource.
- `.../ui/StatusPill.kt` - Kuma-style rounded status badge (colored pill, white text).
- `.../ui/theme/` - `Color.kt`, `Theme.kt`, and `Motion.kt`: semantic Kuma status
  colours over URSA's quiet neutral light/dark surfaces, compact type/shape scale,
  and the shared low-cost motion vocabulary.
- `.../ui/components/` - reusable product surfaces. `UrsaPressableCard` provides
  GPU-only tactile press feedback without list-row layout animation.
- `.../ui/settings/SettingsScreen.kt`, `.../ui/lock/`, `.../ui/push/PushScreen.kt`,
  `.../ui/widget/`, `.../ui/tile/` - settings, app lock, push setup, widget, QS tile.

**exports**
- `UrsaApp()` (Compose entry, hosted by `MainActivity`).
- `UrsaViewModel`: flows `monitors`, `state`, `selectedMonitor`, `beats`, `certs`,
  `favorites`, `login`, `connectionTest`, `connections`, `activeUrl`, `statusPage`,
  `savedStatusPages`, `selectedStatusPageId`;
  actions `login`, `loginWithSessionToken`, `testConnection`, `testSessionToken`,
  `switchTo`, `reauthenticate`,
  `renameConnection`, `removeConnection`, `select`/`back`,
  `pause`/`resume`, `toggleFavorite`, and saved status-page CRUD/order/open/refresh.

**depends on**
- `data/repository`, `core/network` (StatusPageClient), Compose Material 3,
  lifecycle-viewmodel-compose, lifecycle-runtime-compose.

## gotchas

- Routing is a `when` on state, not a nav graph. System back is handled per-screen
  with `BackHandler` (detail → list, server form → server manager, status
  page → login).
- Routing uses `hasSession` (set once authenticated, and optimistically at startup
  if a stored JWT exists) - NOT raw connection state - so reconnects keep the list
  visible with a "Connection: …" banner. `logout()` clears it.
- Saved public pages are encrypted by `StatusPageStore`; public-page URLs never
  duplicate access headers. A page whose normalized base URL exactly matches a
  saved server inherits that server's encrypted headers only at request time.
- Connection summaries show only the number of encrypted access headers. Header
  values are masked during entry and never rendered after save.
- Portable backups merge servers by normalized URL. They include connections,
  access headers, favorites, dynamic-colour choice, and slow-alert preferences;
  session JWTs require an explicit opt-in. Device-bound lock keys, push endpoints,
  cached monitor data, and alert cooldown timestamps are never exported.
- Adaptive launcher and monochrome icons are packaged. Cleartext HTTP is enabled
  in the manifest for self-hosted http instances.
- UI/UX direction, accessibility requirements, and performance gates live in
  `docs/planning/ui-revamp.mdx`. The revamp is active; primary screens may be at
  different migration stages until that programme completes.
