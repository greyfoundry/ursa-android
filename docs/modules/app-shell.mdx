## what this is

The phone app's Android entry point and Compose host. It applies release UI privacy,
restores the encrypted startup route, handles Android 17 local-network permission,
and forwards only validated URSA deep links to the state-driven UI router.

## technical map

- `app/src/main/java/dev/astoris/ursa/MainActivity.kt` - edge-to-edge
  `FragmentActivity`, app lock host, startup intent handling, permission launcher,
  and `UrsaTheme`/`UrsaApp` composition.
- `app/src/main/java/dev/astoris/ursa/core/navigation/AppDeepLink.kt` - strict
  `ursa://` route construction and parsing.
- `app/src/main/AndroidManifest.xml` - launcher/BROWSABLE activity, network and
  notification permissions, widgets, tile, workers, and non-exported receivers.
- `app/src/main/res/values/themes.xml` - XML launch theme before Compose renders.

## deep-link contract

Supported destinations are connection, monitor, incident center, public status
page, notifications, and settings. Private server routes use the first 16 hex
characters of SHA-256 over the normalized saved server URL. URLs, tokens, access
headers, and credentials never appear in an intent URI.

The parser rejects the wrong scheme, user info, unexpected host/path shape, query,
fragment, encoded separators, invalid IDs, and unknown server/page scopes. A valid
route still resolves only against data already saved by URSA.

## gotchas

- Release builds set `FLAG_SECURE`; debug builds intentionally permit QA captures.
- The startup loading surface remains until encrypted connection selection is read.
  Network authentication may continue after that gate without bouncing the user to
  the login form.
- Android 17 local-network access is requested only immediately before testing or
  connecting to an obvious direct LAN address. DNS-SD's system picker is separate.
- Routing remains state-driven rather than using a navigation library. Keep intent
  parsing pure and bounded before changing ViewModel state.
