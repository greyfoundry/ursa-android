## what this is

How URSA is wired together and how data flows from a Kuma server to the screen.
The app is a thin, reactive client: a socket/REST layer feeds repositories,
repositories expose Flows, Compose renders them. Nothing is stored server-side.

## technical map

**data flow**
```
Kuma server ──Socket.IO──▶ core.network (adapter: parse/normalize wire → domain)
            ──REST(Ktor)─▶        │
                                  ▼
                          data.repository (StateFlow<DomainModel>, single source of truth)
                                  ▼
                          ui.* (Compose, collectAsStateWithLifecycle)

core.storage (DataStore+Tink)  ── credentials/JWT ──▶ core.network (login/loginByToken)
distributor (ntfy) ──push──▶ core.push (UnifiedPush receiver) ──▶ system notification
```

**layers (M1 implemented unless noted)**
- `core.network` → `.../core/network/` (KumaClient, KumaParse, StatusPageClient) -
  see `docs/modules/network.mdx`.
- `core.storage` → `.../core/storage/` (ConnectionStore, encrypted caches,
  preferences, event history, and incident notes) - DataStore with Tink
  AES-256-GCM at rest, master key in Android Keystore.
- `core.push` → `.../core/push/` (UrsaPushService, PushParse, PushStore) -
  UnifiedPush receive path + notification rendering. See `docs/modules/push.mdx`.
- `data.model` → `.../data/model/` - Models.kt + StatusPageModels.kt.
- `data.repository` → `.../data/repository/MonitorRepository.kt`.
- `ui.*` → `.../ui/` (UrsaViewModel, UrsaApp, connections/monitors/statuspage) -
  see `docs/modules/ui.mdx`.
- app shell → `.../MainActivity.kt` - see `docs/modules/app-shell.mdx`.

**depends on**
- `docs/references/*` - the external API contracts each layer implements against.

## gotchas

- The adapter in `core.network` is the ONLY place that knows Kuma's wire quirks
  (positional events, snake/camel split, double-encoded JSON). Keep it there.
- One `Socket` per active server; multi-server = switch the active repository, not
  multiple live sockets in v1.
- Push is independent of the socket - it works while the app is closed, via the
  distributor. Don't couple them.
